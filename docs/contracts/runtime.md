# Executable backend contract — Task 1

Engineering implementation, not a device/provider/AWS qualification. No live delivery, audio transcription or automatic nonresponse escalation is enabled. All test identities, phones and trips are synthetic.

## Run and identity

Node 24–26, PostgreSQL 15+ (tests ran PostgreSQL 18). `npm ci`, `npm run build`, `DATABASE_URL=... npm run migrate`, then configure `.env.example` through the environment and `npm start`. Migration is a separate one-off command, never API startup. `npm test` builds first and requires `TEST_DATABASE_URL` to a disposable database; each test creates/drops a unique schema.

`src/api/app.ts` exports `createApp({ctx,auth,channelSupport?})`, a Fastify instance; `await app.close()` closes all context pools. `auth` requires trusted `issuer`, `audience` and HTTPS `jwksUrl`; an injected jose `keyResolver` is available to signed-key tests. Production `src/server.ts` only reads trusted OIDC environment, supplies no synthetic resolver and supplies **zero channel support**. JWT signature, RS256/ES256 algorithm, issuer, audience, required subject/expiration and time validity are verified by jose. No body ID grants identity or ownership. There is no role/account bypass.

Identities map `(issuer, subject)` to a server UUID. `GET /v1/me` returns `{id}` and registers/updates the authenticated identity. A phone is eligible only from a valid E.164 `phone_number` and literal true `phone_number_verified` trusted claim. Phone claims refresh in SQL each authenticated request. Contact acceptance checks the current authenticated claims against the frozen invitation destination; dispatch must recheck the SQL identity phone/verification and grant destination.

API JSON object schemas reject extra fields and type coercion. HTTP bodies are limited to 128 KiB. Every POST requires `Idempotency-Key` (1–128 visible ASCII characters), is transactional, and responds 200 when successful. Keys are scoped to authenticated actor, method, route and path params. Same key/content returns the persisted original response; changed JSON content returns 409. Object key order is ignored. Errors return `{code}`: validation 400, unauthorized 401, ownership/consent denial 403, missing object 404, state/idempotency conflict 409, unsupported audio 422, and redacted internal error 500. Responses use `Cache-Control: no-store`.

## HTTP routes

| Route | Body / behavior |
|---|---|
| `GET /health` | Unauthenticated DB readiness `{status:'ok'}`; DB failure 503. |
| `GET /v1/me` | Authenticated identity `{id}`. |
| `POST /v1/trucks` | `{label}` → `{id}` owned by the authenticated driver. No fleet account. |
| `POST /v1/contacts` | `{contactId,phone,map,incident}` creates one pending standing invitation per driver/contact. Target must already have registered identity. At least one scope; driver cannot invite themselves. Returns `{id,status:'pending'}`. No message is sent. |
| `POST /v1/contacts/:id/accept` | `{map,incident}` under the target contact identity and matching verified phone. Requested scopes may be narrowed; never broadened. Returns `{id,map,incident,status:'accepted'}`. |
| `POST /v1/contacts/:id/revoke` | `{}` by driver or target contact permanently revokes standing consent plus all current trip grants and cancels their pending/claimed jobs. Future confirmation cannot select this standing invitation. Returns `{id,revoked:true}`. Re-enrollment is not implemented; driver cannot restore revoked consent. |
| `POST /v1/trip-drafts` | `{text,fields?}` with untrusted text, optional partial corrected fields. Fields: `truckId,origin,destination,country,locale,timeZone`. Returns `{id,rawText,fields,missingFields,status:'draft'}`. Missing fields persist without activation. Any `audio` field returns `unsupported_audio` (422). No fabricated extraction/transcription. |
| `POST /v1/trip-drafts/:id/confirm` | `{confirmed:true,contactGrantIds:[],fields?}`. Optional corrected fields merge into stored draft. Complete fields and owned truck required; selected standing contacts must be accepted and unrevoked. Maximum ten unique grants, normalized to lowercase UUIDs before duplicate checking and locking. Returns `{id,status:'active',fields}`. Trip ID equals draft ID. Reconfirmation under another key returns 409. No country/time-zone defaults. Country is two uppercase letters; locale/time zone validate using Intl. |
| `GET /v1/trips/:id` | Driver-only persisted trip row (SQL field names; dates serialized as ISO). |
| `POST /v1/trips/:id/commands` | `{type:'arrived'|'cancel'|'pause'|'resume'|'checkin_ok'|'rest_report'}`. Owner only. Closure stops map/checkins and pending/claimed ordinary jobs atomically; it preserves active SOS and prior authorized work. Pause stops checkins/ordinary pending work, without silently stopping map. OK/rest are attributed self-report events, not fatigue detection or incident resolution. Returns `{id,command,automaticEscalation:false}`. |
| `POST /v1/trips/:id/locations` | Owner-only `{observations:[{capturedAt,latitude,longitude,accuracy}]}`; 1–100 samples. Captures older than 24h or >30s in future rejected. Latest only advances by capture timestamp; duplicate timestamps preserve first committed sample. History prunes to 500 samples / 24h at upload. Latest is separate. Closed trip rejects new uploads. Returns `{id,received}`. |
| `GET /v1/trips/:id/snapshot` | Owner or current accepted map contact; live standing/trip consent and map-active checked under trip lock each read. `{tripId,location,freshness,ageMs,readAt}`. `location` contains `capturedAt,receivedAt,latitude,longitude,accuracy`, or null. `freshness` is fresh up to 120s, stale after, unavailable if absent. Captured, received and read time remain separate. No bearer/share-link issuance. |
| `POST /v1/trips/:id/contacts/:grantId/revoke` | `{}` by driver or that contact; stops only this trip grant, blocks subsequent map/incident reads/authorizations and cancels pending/claimed recipient jobs. Returns `{id,tripId,revoked:true}`. |
| `POST /v1/trips/:id/sos` | `{}` owner only, including after trip close. Creates/returns one active incident and records an attributed report. Returns `{id,tripId,status:'active',groupCapability:'unavailable'}`. New keys/taps share the active episode; after explicit resolution a new episode is possible. |
| `POST /v1/incidents/:id/acknowledgements` | `{}` by current incident-consented contact. Records attributed acknowledgement; does not cancel work or resolve. Returns `{id,status:'active',recorded:'acknowledged'}`. |
| `POST /v1/incidents/:id/actions` | `{action}` by current incident-consented contact; records reported action, not independently verified help. Returns `{id,status:'active',recorded:'action'}`. |
| `POST /v1/incidents/:id/resolve` | `{}` owner only. Resolves incident and cancels pending/claimed incident jobs; leaves trip/map independent and prior authorized work intact. Returns `{id,status:'resolved'}`. |

Freshness, sample/retention and 15-minute job expiry values are synthetic engineering bounds, not validated safety cadences/deadlines. Old history is trimmed at subsequent upload; there is no claim of a completed retention/deletion scheduler. Latest/location, raw draft and audit data need a separately qualified deletion policy before live collection.

## SQL and worker seam

`src/db.ts` exports `createContext(databaseUrl,clock?)`, `transaction(pool,SQLCallback)`, `withTripTransaction(ctx,tripId,SQLCallback,pool?)` and `migrate(pool)`. Context owns `pool` (command capacity 6), `telemetryPool` (2) and `callbackPool` (2), each with 3s connection acquisition timeout, 5s statement/idle-transaction timeout and 30s idle timeout. Pool failures never log secrets. Telemetry authentication, upload and snapshot use telemetry capacity; command/SOS use command capacity. The clock is `() => Date`. Workers must budget extra pools across replicas rather than silently consuming API reservations.

`withTripTransaction` begins, `SELECT trips ... FOR UPDATE`, executes only SQL/state code, commits/rolls back and always releases its client. Never call network/provider/SQS while holding this transaction. Snapshot, upload, trip commands, per-trip revoke, incident mutation and authorization share this trip-row serialization point; no dispatch fence exists.

Standing acceptance/revoke and confirmation lock stable standing grant IDs with **`FOR NO KEY UPDATE`**, not `FOR UPDATE`. Standing revoke takes the grant row first, then every referencing trip row in native UUID order, updates standing/trip revocation and pending jobs, and commits. Confirmation locks its draft, normalizes selected UUIDs to lowercase, rejects case-alias duplicates, then takes grant locks in canonical UUID order **before inserting its new trip**. Existing-trip operations (including worker authorization) lock trip rows and read standing grants without additional explicit grant row locks. Their SQL inserts can still acquire **implicit foreign-key `KEY SHARE` locks** on standing grants; these are compatible with `NO KEY UPDATE`. Using `FOR UPDATE` for the standing grant would conflict with that implicit FK lock and deadlock against the trip-row wait. Do not change grant primary keys or upgrade grant locks in these paths. This lock compatibility plus stable ordering serializes revoke with existing-trip authorization and concurrent new-trip insertion. Authorization-first may finish later; revoke-first must deny. Worker authorization must recheck both `contact_grants.revoked_at` and `trip_grants.revoked_at`, accepted scope, subject/destination verification and current trip/incident state in its trip transaction.

Migration `001-core.sql` is immutable once applied; `schema_migrations(version,hash)` plus a migration-only advisory lock make repetition/concurrent invocation safe and changed applied SQL fail closed. Task 2 may add numbered migrations and extend the runner. SQL tables:

- `identities`, owned `trucks`, `trip_drafts`, `trips` (version, map/checkin states), standing `contact_grants`, selected `trip_grants` (revocation attribution).
- `locations`, `latest_locations`; latest changes only for newer capture time.
- `incidents`, partial unique active incident per trip; `trip_events`, `incident_events` distinguish SOS report, receipt/action and driver resolution.
- `idempotency(actor_id,scope,key,request_hash,response,created_at)` with unique actor/scope/key, canonical content hash and short transaction-scoped per-key advisory lock. Advisory locks are never held for dispatch/network.
- `jobs(id,trip_id,incident_id,grant_id,recipient_id,channel,class,version,status,unavailable_reason,created_at,due_at,expires_at,cancelled_at)`. `channel`: sms/whatsapp/voice/group. `class`: emergency/ordinary. Status allows pending, claimed, authorized, accepted, rejected, unknown, delivered, cancelled, unavailable. Incident/recipient/channel has a partial unique index with nulls not distinct (one group fact, distinct individual channels); ordinary jobs with no incident are not constrained by that incident index. Task 2 adds lease/attempt/quota details. Statuses represent facts, never inferred delivery.
- `outbox(id,job_id,job_version,class,created_at,published_at,lease_owner,lease_until,next_publish_at)`, unique job/version, due index. Initial eligible SOS jobs/outbox are inserted atomically. Queue payload may contain only IDs/version/class, never phone, raw text or coordinates. Version mismatch/cancelled SQL job must prevent new authorization even if an old outbox message publishes.

SOS snapshots accepted unrevoked incident recipients, deduplicated by standing driver/contact uniqueness, and creates separate SMS/WhatsApp/voice jobs immediately. Missing country/channel/locale support or mismatched current verified phone creates explicit unavailable jobs with reasons and **no outbox**. A separate group job is always unavailable with `group_support_unverified`; individuals never substitute for group delivery. Only test factory options currently supply synthetic support. Production supplies none. This slice performs no external send and contains no provider adapter.

Close, resolve and either revoke cancel only pending/claimed affected jobs (incrementing job version); authorized/unknown/in-flight facts remain. Stale transport must be rechecked against SQL. Trip closure never automatically resolves SOS, and SOS after closure must never gain fresh map coordinates. Contact ack/action needs incident consent but does not require active map, so an open security episode can continue after arrival without fresh coordinates. Fields in `src/contracts.ts` export Actor, Trip, Job, Outbox and Channel/ChannelSupport for the next runtime slice.

## Task 2 — executable durable dispatch

`npm run build` then `npm run migrate` applies ordered, hash-checked numbered SQL migrations, including `002-dispatch`; `001-core.sql` remains unchanged. API `npm start`, control `npm run worker:control`, emergency `npm run worker:emergency`, ordinary `npm run worker:ordinary` are separate processes/services built from the same image. No migration runs on startup. Workers require `DATABASE_URL`, `AWS_REGION`, `SQS_EMERGENCY_URL`, `SQS_ORDINARY_URL`; use task-role AWS credentials and HTTPS Standard queues, with separate DLQs. SQS permissions: control `sqs:SendMessage`; each consumer `sqs:ReceiveMessage`, `sqs:DeleteMessage`, `sqs:ChangeMessageVisibility` on its class queue. No blind DLQ redrive grants sending authority.

The API reserves at most **10 connections per replica**: commands 6, telemetry 2, callbacks 2. Each worker uses at most **2 command connections**; its unused lazy telemetry/callback pools open no connections. Budget RDS connections as `10*API replicas + 2*(control+emergency+ordinary replicas) + migration/operations headroom`; replicas and database capacity must be explicitly capped by infrastructure. The initial delivery role has two slots independently for each of SMS, WhatsApp and voice (six external calls maximum per replica), across all receive batches. SQL decides the channel before a slot is assigned. Saturated messages get 30-second SQS visibility deferral, leaving the receive pump free for other channels. No SQL client/transaction is held during SQS or provider I/O. Control relay, scanner and each channel's read reconciliation run independently. SIGINT/SIGTERM abort long polls and provider HTTP; already authorized calls become unknown if acceptance cannot be determined. Provider fetch has a 10-second client timeout with no HTTP retries or redirects; this is an engineering resource bound, not a safety deadline or server cancellation guarantee.

`src/notifications/dispatch.ts` exports `relayOnce`, `recoverWork`, `claimJob`, `authorizeJob`, `runJob`, `finishAttempt`, `reconcileOnce`, `saveCallback`, `consume`; `src/worker.ts` exports `control` and `startWorker`. `src/notifications/sqs.ts` is the actual AWS SDK v3 adapter. Queue JSON has exactly `{jobId,version,class}`, no channel, phone, text or location. Runtime uses real AWS transport only; there is no synthetic startup fallback. SDK transport retries can duplicate queue publications, never provider attempts.

The SQL lease is 30 seconds. Relay updates use unique ownership tokens; an old publisher cannot acknowledge a newer lease. Lost publish acknowledgements republish only transport, with persisted exponential backoff up to five minutes. Scanner runs every second and restores pending jobs/outbox after lost/expired transport no sooner than 60 seconds after a confirmed publication. Claimed work without an external attempt can be reclaimed after expiry; stale tokens cannot authorize. A unique `dispatch_attempts.job_id` permits one external attempt per job. SQL authorization rechecks current standing/trip consent, incident scope, matching verified destination, incident owner/state, class, version, due time, expiry and qualification while holding the existing trip-row lock. Standing grants are read without upgrading the `NO KEY UPDATE` lock graph. A crash after authorization yields unknown, never pending. Queue replay and scanner cannot create another external attempt, even after HTTP 404 reconciliation or a rejection. This first version makes **no automatic provider resend at all**; a rejection needs operator review, and a genuinely new driver-declared episode requires explicit resolution/new SOS. It must not be used as a workaround to resend an ambiguous prior episode.

Every authorized attempt freezes the provider payload, its SHA-256 hash, destination hash, owner/token and stable provider key before network. The alert summary attributes the driver/trip and incident creation ISO timestamp/time zone. It includes last latitude/longitude, capture timestamp, accuracy and a recent/old label only when map access and standing/trip map consent remain valid at authorization. The existing 120-second freshness bound is synthetic. Otherwise it truthfully says `ubicación no disponible`. Arrival keeps SOS active while preventing newly authorized payloads from gaining coordinates. Payloads already authorized may finish after revoke/closure. Untrusted raw trip text is never copied. WhatsApp places the entire summary in one explicitly configured approved-template variable; text and voice append it to qualified configured text. Incident acknowledgements/actions remain separate from provider acceptance/delivery.

### Provider configuration and evidence

The default `ZAVU_LIVE_SEND=false` gives API zero supported channels; delivery-role startup refuses to send without complete configuration. To enable actual sending, set the literal `ZAVU_LIVE_SEND=true`, inject server-only `ZAVU_API_KEY`, `ZAVU_PROJECT_ID`, `ZAVU_SENDER_ID`, `ZAVU_CALLBACK_SECRET`, and `ZAVU_QUALIFICATION_JSON`. The JSON must contain:

- `accountId` equal to `ZAVU_PROJECT_ID`, `senderId` equal to `ZAVU_SENDER_ID`, nonempty `evidence` referencing actual account/balance/limit qualification.
- Positive integer `dailyLimit`, `channelDailyLimit`, `minuteLimit`; nonnegative integer `emergencyReserve` smaller than all three. These are explicitly qualified conservative account budgets, not public Zavu defaults. They must cover account traffic from all applications, not just this service.
- `entries`: unique `{channel,country,locale,evidence,text}` objects. Country is an explicit two-letter uppercase code, locale a canonical Intl locale, evidence references sender/destination/channel qualification, and text is approved localized safety copy. Voice additionally needs `voiceLanguage` exactly `es-ES` or `pt-BR`; WhatsApp additionally needs account-approved `templateId` and `summaryVariable` (one documented positional or named string key). Template qualification must allow the full timestamp/location summary. No group entry is supported. A nonempty evidence reference is a configuration assertion, not independently verified by code; operators must verify its contents before enablement. Test-only fixtures explicitly use `syntheticfixture:` evidence and are rejected by production environment loading.

`quota_reservations` persists send reservations per account/channel/day. `provider_requests` persists all send/read request reservations for a sliding minute, including across UTC midnight. Account-row locks serialize replicas. Ordinary sends and background reconciliation leave the configured emergency margin; emergency sends can use it. Reservations are conservative and retained after refusal/timeout. Actual rate enforcement occurs at authorization/read reservation time; delayed already authorized emitters and external account users can still encounter provider throttles. Refusals are recorded without automatically sending again. Quota denial returns an unattempted job to SQL pending, due in one minute; scanner restores transport. There are no validated price/cost assumptions: these count limits bound usage, not a currency billing guarantee.

`POST /v1/callbacks/zavu` is registered only with complete callback context. It uses a separate two-connection pool and exact raw `application/json` bytes. No OIDC token or API idempotency key is required; strict v2 HMAC authentication uses the configured project/sender/secret, exact `t + '.' + bytes`, constant-time comparison and documented -300/+60-second window. Durable `(project,eventId)` dedupe and evidence commit precede 200; storage failure returns 500. No raw payload, signature, phone, coordinates, freeform provider error text or credential is logged/stored as callback evidence: only exact-byte SHA-256 hash, selected verified IDs/status/type, hashed destination, safe error code and timing. Minimal event evidence expires after seven days and scanner deletes it; dedupe consequently has that same retention. Sensitive attempt payload expires after 24 hours and scanner clears it, preserving hashes/facts for unresolved attempts; quota windows prune after two days. These are explicit synthetic engineering retention bounds, not legal/data-policy qualification. Core API/audit/location retention still needs the separate policy noted above.

Callbacks arriving before HTTP response remain unmatched by exact message ID. Only a subsequently persisted response ID can map them; phone/time/text never correlate attempts. Timeout without ID remains unresolved, even if a matching-phone event exists. Reconciliation only GETs the known official message ID; it never POSTs or lists by guessed correlation. ID/channel/destination must match read evidence. Delivered/read facts do not regress under late queued, failed, unknown or HTTP timeout results. Voice receipts remain evidence without claiming human answer/playback semantics; existing-group sends remain unavailable. Source-unspecified key TTL, cancellation and read-only key lookup remain unsupported. See [Zavu research](zavu-research.md) for exact source contracts and qualification gaps. No test key is safe for network tests.

# ANDES route/task map

All routes are utility/private task routes. No public search acquisition surface is in scope. No SERP, rankings, volume or marketing claims are fabricated. Dynamic identifiers must be bound to authorised synthetic fixtures by the capture harness; they are route patterns, not evidence URLs. Origin is deliberately unbound until an owned local preview is reserved.

- / → home task, owner50; See current trip or prepare the next freight trip.
- /session → session task, owner49; Enter an actually supported authenticated or explicitly synthetic local session.
- /trucks → trucks task, owner50; Read and register owned freight trucks.
- /contacts → contacts task, owner51; Invite accepted trusted contacts and control scoped sharing.
- /trips/new → trip-new task, owner50; Correct a text draft and explicitly confirm truck, route and accepted contacts.
- /trips/:tripId → active-trip task, owner50; See source-aged facts and use explicit permitted trip commands.
- /trips/:tripId/check-in → check-in task, owner50; Report OK or rest only in an available interaction mode.
- /trips/:tripId/alerts → alerts task, owner50; Separate local intent, server acceptance, channel facts and contact response.
- /contact/trips/:tripId → contact-trip task, owner51; Read only current authorised facts and report contact action without claiming rescue.
- /contact/invitations/:grantId → invitation task, owner51; Accept or narrow scopes for this authenticated invitation.
- /trips/:tripId/summary → summary task, owner50; Read persisted trip events and unresolved incident facts separately.
- /privacy → privacy task, owner51; Inspect and revoke operational sharing and understand separate optional reuse.

Uniqueness: each intent has one owner; no discoverability keyword target, location clone, repeated homepage keyword or route with invented business proof. Metadata on authenticated trip/contact views is generic and noindex; privacy takes precedence over marketing metadata.
